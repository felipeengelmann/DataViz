Guidelines

Which palette, when — and the rules that keep charts honest.

Color in a chart answers exactly one question. Decide what the question is, pick the palette built for it, and never mix palettes inside one chart. Each rule below is tagged for the people who act on it.

1 · What does color encode?

Start here for every chart. The answer names the palette; the palette names the tokens.

Groups with no natural order
Categorical
Device types, apps, OS versions, regions, teams. Up to 10; stop at 5–7 when you can.
A judgement or a state
Status
Severity, health, compliance, utilization bands, availability. The same color means the same thing everywhere.
One quantity, low → high
Sequential
Counts, percentages, age, duration — on maps, heatmaps, calendar grids. Use the 7-step ramp when the grid is dense.
A value against a midpoint
Diverging
Above / below benchmark, change since last period. Neutral direction only — judged direction is Status.
One series matters, the rest is context
Emphasis
Selected device vs. fleet, this app vs. others, actual vs. target band.
Exactly two states
Binary
Neutral pairs use categorical 1 + 2; judged pairs (compliant / not) use positive + negative.
Change in a KPI
Trend delta
Color says better / worse / same; the arrow says up / down. Never let “down” default to red.

Offline is not an error. A powered-down laptop is neutral gray. Only make it red when the product has decided that offline is a problem — and then call the state something else (“Unreachable”).

3 · Rules

Short, checkable, and tagged. A chart that breaks one of these is a bug, not a taste difference.

One palette per chart
A donut is categorical or status, never both. If a chart needs to show “which group” and “how healthy”, split it: color for one, position or a second chart for the other.
Use categorical colors in order
1 → 2 → 3 …, stop at the count you need. Never skip to a “nicer” color. Order is what guarantees adjacent contrast and color-blind separation.
Same entity, same color, whole page
If Printers are copper in the inventory bar, Printers are copper in the crash trend. Decide the binding once per page (or per product area) and write it in the spec.
Green is for good. Only good.
Never use green as the “low” end of a severity scale, as a categorical color in a chart that also shows health, or for “complete” unless completion is the positive outcome.
Color is never the only channel
Direct labels or a legend for every series; markers or dash patterns when more than 4 lines overlap; a hatch for “no data”; arrows on deltas. Color confirms — text and shape carry.
Labels on fills use the token’s label color
Every fill token carries a companion label color (white or ink) that reaches 4.5:1. In Highcharts set dataLabels.style.color from it — do not rely on the default contrast heuristic in dark mode.
Blue in a chart is data, not a link
Categorical 1 and the info state use the data blue (#3363D2), not the brand blue. Do not place clickable text in brand blue inside a chart card that uses blue fills.
Dark mode is a token switch, not a filter
Every token has a light and a dark value. Read the mode value; never invert, lighten or set opacity on the light value at runtime.

4 · Accessibility bar

EN 301 549 (the European accessibility standard behind the EAA) points at WCAG 2.1 AA. These are the criteria that touch charts, and how the palettes meet them.

Criterion
What it asks
How we meet it
1.4.11 Non-text contrast
Graphical parts needed to understand content reach 3:1 against adjacent colors.
Every categorical and status fill is ≥ 3:1 against its surface in both modes (values on the Palettes page). Adjacent stacked segments are separated by a 1px surface-colored border so neighbours never have to contrast with each other.
1.4.3 Contrast (minimum)
Text reaches 4.5:1 (3:1 at ≥ 24px / 19px bold).
Axis labels, legends and tooltips use chrome tokens at ≥ 4.5:1. Labels on fills use the token’s companion label color. Trend-delta text colors pass as text.
1.4.1 Use of color
Color is not the only way to convey information.
Legends or direct labels always present; “no data” is hatched; deltas carry arrows; lines beyond four series get markers or dashes; tables show the state name next to the dot.
Color vision (best practice)
Not a WCAG criterion, but ~8% of men are affected.
Palette order alternates lightness so deuteranopes and protanopes separate neighbours; sequential and multi-hue ramps change lightness monotonically; simulations are shown per swatch on the Palettes page.
Sequential exception
The lightest 2 steps of a ramp are below 3:1 by nature.
Ramps are read relatively, so cells get a gap or hairline border, the legend shows the full ramp with labels, and no threshold that matters lives in a step under 3:1.

5 · Implementation notes for Highcharts

Tokens are the API. Charts read them; nobody types a hex.

// tokens/dataviz.tokens.json → resolved for the current mode
const t = resolveTokens(tokens, mode); // 'light' | 'dark'
 
// Global default: categorical order + chrome
Highcharts.setOptions({
  colors: t.categorical, // 10 hex values, in order
  chart: { backgroundColor: 'transparent', style: { fontFamily: 'inherit' } },
  xAxis: { lineColor: t.chrome.axis, tickColor: t.chrome.axis, labels: { style: { color: t.chrome.label } } },
  yAxis: { gridLineColor: t.chrome.grid, labels: { style: { color: t.chrome.label } } },
  legend: { itemStyle: { color: t.chrome.title } },
  tooltip: { backgroundColor: t.chrome.tooltipBg, style: { color: t.chrome.tooltipText } },
  plotOptions: { series: { borderColor: t.surface, borderWidth: 1 } }
});
 
// Status: bind by key, never by index
series: alerts.map(s => ({
  name: s.label, data: s.values,
  color: t.status[s.severity].hex, // 'critical' | 'high' | …
  dataLabels: { style: { color: t.status[s.severity].label } }
}))
 
// No data: hatch via modules/pattern-fill.js
color: { pattern: { path: 'M 0 0 L 8 8', color: t.status.noneHatch, width: 8, height: 8, backgroundColor: t.status.none.hex } }
Token shape. dataviz.<palette>.<key> with a $value of { light, dark } (DTCG format). Ramps are numbered from lightest/lowest: sequential.blue-7-1 … 7.
Mode switch. Re-resolve tokens and call chart.update(themeFor(mode)). Do not toggle CSS filters on the SVG.
Sequential and heatmap. Use colorAxis.dataClasses with 5 or 7 classes taken from the ramp — not stops interpolation, which produces unnamed in-between colors that no legend can describe.
Emphasis. Set color: t.emphasis.muted on context series and t.emphasis.primary on the highlighted one; reference bands use plotBands.color = t.emphasis.faint.
Load the accessibility module. modules/accessibility.js adds keyboard navigation and screen-reader descriptions; color work alone does not make a chart accessible.

6 · What a spec has to say about color

Four sentences in the spec remove most color debates.

1
What does color encode?
“Color = device type” or “color = alert severity”. One answer per chart.
2
Is there a judgement?
If yes, name the good end and the bad end, and say whether “higher” is better. That decides Status vs. Diverging vs. Trend colors.
3
How many values, worst case?
Above 7 categories the design must group a tail into “Other” — say what goes in it.
4
What are the thresholds?
For status bands and gauges: the exact cut-offs (e.g. > 90% memory = critical) so colors are computed, not eyeballed.
