Specimen surface
Data viz library · palette expansion

Ten categorical colors, a status scale that reads in order, sequential and diverging ramps, and an emphasis technique — in light and dark.

Every fill meets WCAG 2.1 AA non-text contrast (3:1) against its chart surface, which is what EN 301 549 (the European accessibility standard) requires. Label colors are pre-computed so text on fills reaches 4.5:1. Existing system colors stay untouched; status values are drawn from them.

Assumptions I made
  • Chart surfaces are white in light mode and #212121 containers in dark mode, per the system tokens.
  • Blue stays the interactive color, so categorical #1 is a softer, brand-adjacent blue rather than #024AD8.
  • Categorical and status palettes are never mixed in one chart — that rule is what lets both stay expressive.
  • Color-blind safety is “balanced”: neighbours in palette order stay apart under deuteranopia and protanopia; the first five are the safest subset.

Categorical

dataviz.categorical.01–10

Unordered groups: device types, apps, regions, OS versions. Warm and cool hues alternate so stacked neighbours contrast; lightness alternates deep/mid so the order survives color-vision deficiency. Use colors in order and stop at the count you need — never skip or shuffle.

1–5 for most charts. Blue, copper, teal, magenta, moss are the highest-separation subset in every simulation. If a chart needs more than 7 series, group the tail into “Other” (color 10, slate).
Dark mode is a separate set, not the light set inverted. Each color is lightened until it clears 3:1 on #212121; labels on fills switch to dark ink.
Colors keep their meaning across charts on a page. If “Printers” is copper in the donut, it is copper in the trend line. Bind colors to category keys, not to series index.

Status

dataviz.status.*

One ordered severity scale — critical → high → medium → low — that darkens and warms as it gets worse, plus three outcome colors. Green means good and nothing else; gray means no judgement. All eight values are existing system primitives (or the data blue), so chips, badges and charts agree.

Why the old set felt odd: red → orange → yellow → green → gray put a “good” color inside a severity ramp, so “low” read as “fine”. Here low is a gold that is still clearly a warning, and green only appears when the outcome is positive.
Critical uses the system’s critical pink-red, one step darker than high in light mode so the two never blur in a stacked bar. Dark mode uses the system’s dark critical and negative bases as-is.
Light-mode low is #BA7E15, not the caution yellow. Yellow-3 is 1.9:1 on white and fails as a fill; chips keep yellow because they pair a tint background with dark text.

Sequential

dataviz.sequential.blue-7-* · blue-5-*

One quantity, low → high: device counts by region, utilization %, age of hardware. Single-hue brand blue with evenly spaced perceptual lightness steps (OKLCH). Pick 5 steps for binned legends, 7 for heatmaps with more range. In dark mode the ramp runs dark → bright so “more” still reads as “brighter”.

Diverging

dataviz.diverging.blue-copper-1…7

A value against a midpoint: below / above benchmark, change vs. last period, deviation from a target. Blue and copper are the classic color-blind-safe pair and carry no good/bad meaning — use it when the direction is neutral. When the direction is a judgement (worse ↔ better), use the status palette’s negative and positive ends instead.

Held in v1: Multi-hue and Heatmap severity Not for new charts
Multi-hue is only recommended for dense heatmaps, and its hues clash with categorical colors on the same dashboard. Use the 7-step Sequential ramp instead.
Heatmap severity shows the same meaning as Status with a second set of reds. Use Status classes (critical → low) for severity heatmaps.
The tokens stay in tokens.json, marked as held, so existing charts don’t break while they are migrated. A held palette can return through a registry request. See the palette decision.

Multi-hue sequential

dataviz.multihue.7-1…7 · same values in both modes

Dense, continuous data where a single hue runs out of distinguishable steps: large heatmaps, density plots, geographic detail. Lightness rises monotonically from indigo to pale yellow, so the order survives every color-vision deficiency, and hue adds resolution. Because the ends are dark and light, one scale serves both modes.

Heatmap · severity

dataviz.heatmap.severity-1…5

Risk and severity matrices (likelihood × impact, alerts by group × week) where “more” means “worse”. The ramp walks the status hues — gold → orange → red → critical — so it agrees with status chips elsewhere on the page. For neutral intensity (counts, volume) use the blue sequential instead.
